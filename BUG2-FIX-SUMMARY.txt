BUG #2 FIX: Container ActionHandler Timeout - REFACTOR COMPLETE
================================================================================

PROBLEM:
--------
120+ container integration tests were failing with "movement executor not set"
errors after waiting 120-135 seconds for timeout.

ROOT CAUSE:
-----------
MovementExecutor was never being initialized. Tests had to manually create:
  1. ItemUsage
  2. InventoryManager
  3. ContainerHelper
And manually call SetContainerHelper() on the agent.

This was error-prone and easy to forget.

SOLUTION IMPLEMENTED:
---------------------
Refactored agent.Init() to automatically initialize ContainerHelper with all
required dependencies. Tests no longer need to do manual setup.

CHANGES MADE:
-------------

1. agent/agent.go (~30 lines added at end of Init)
   └─ Automatic ContainerHelper initialization
   └─ Creates ItemUsage, InventoryManager, ContainerHelper
   └─ Sets version-specific container handler
   └─ Logs initialization status

2. testing/container_suite_test.go (SetupTest)
   REMOVED: 11 lines of manual handler setup
   ADDED:   Comment about automatic initialization

3. testing/container_suite_test.go (TearDownTest)
   CHANGED: Use agent.CloseContainer() instead of s.containerHelper.CloseContainer()
   REMOVED: Cleanup assignments for itemUsage, invMgr, containerHelper
